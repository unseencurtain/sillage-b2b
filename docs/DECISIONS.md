# DECISIONS

Locked choices and the reasoning behind them. If you want to change one, change it here first.

| # | Decision | Why |
|---|---|---|
| 1 | Currency is EUR everywhere, no FX conversion | Both vendors quote EUR — confirmed from BeautyFort's delivery-option response, not assumed. `fx_rate` exists in the schema at `1.0` purely so a future non-EUR vendor needs no migration |
| 2 | Price is `vendor_price × fx_rate × multiplier`, a plain float | `0.5`, `1.2`, `2` all valid. No percentage arithmetic to get wrong |
| 3 | RRP is used as the regular price only when `0 < rrp ≤ 10 × computed` | BTS `recommended_price` is `0` on 46% of rows and peaks at €42,795 against a €889 real-price ceiling. Unclamped you ship listings reading "was €42,795, now €30" |
| 4 | Two databases, one MariaDB server | One server keeps cross-database writes inside a single ACID transaction. Two databases keep sillage-core independently developable and testable |
| 5 | Bun performs every bulk write via raw SQL; PHP performs none | The writes were always going to be parameterized SQL. Only request-time rendering, the search query, and WooCommerce's own cache invalidation genuinely need a WordPress context |
| 6 | SKU is `{PREFIX}-{vendor_product_id}` (`BF-L526676`, `BTS-64220`) | Raw EAN cannot work — BeautyFort rows carry up to 26 of them. Raw vendor ID risks cross-vendor collision |
| 7 | Cross-vendor dedupe by EAN, on by default | 2,646 EANs appear in both feeds. Without dedupe those become duplicate listings. Neither vendor is consistently cheaper, so cheapest-in-stock-wins has real margin value — and it gives Stage 2 automatic vendor failover |
| 8 | Primary offer selection is destination-aware | BeautyFort ships to 7 countries, BTS to 28. A France-bound order cannot be filled by BeautyFort, so the cheapest offer is only a candidate if its vendor serves the destination |
| 9 | Vanished from feed → soft-hide, never delete | Hard deletion orphans order history |
| 10 | Below stock threshold → hidden **and** `outofstock` | Catalog/search exclusion alone still leaves the product addable to cart via a direct link |
| 11 | Threshold comparison is `stock <= threshold`, inclusive | |
| 12 | Product slug is `slugify(name) + '-' + sku` | Unique by construction, so no collision-check round trip and re-runs stay idempotent |
| 13 | Call-interval fast sync (price/stock); routine daily full catalogue rebuild; Rebuild on Sync is the manual escape | A full pipeline every 30 min would rewrite ~1M postmeta rows to change a handful of prices. Daily download caps were retired — only the per-vendor call interval blocks a live fetch. `full_sync_enabled` is the routine path for new SKUs and BTS `product_cat` creation. BTS 25%/7-day unseen recovery stays emergency-only |
| 14 | Brands go to the native `product_brand` taxonomy (singular) | WooCommerce 9.4+ ships it. Free brand archives and filtering. The plural spelling is not registered and fails silently |
| 14b | External images are served by faking the attachment layer, never by overriding a theme's gallery | A product reports its own post ID as its thumbnail ID, and `image_downsize` resolves that ID to the vendor URL. Every theme, the REST API, wp-admin and structured data go through those filters, so nothing is theme-specific. Overriding gallery renderers needs new code per theme and breaks silently when the theme changes |
| 14c | The plugin must work on any theme; the storefront theme is not fixed | Currently Blocksy, moving to Astra. Theme-specific code is allowed only as a guarded, additive shim (e.g. rebuilding Blocksy's lookup table), never as the mechanism something depends on |
| 15 | Primary EAN also written to `_global_unique_id` | WooCommerce's native GTIN field — adds wp-admin search and schema.org markup at no cost |
| 16 | BTS gender is derived from its category tree, not its `gender` field | The field is 98.4% `unisex` and therefore useless as a facet. BeautyFort encodes gender properly in its category path |
| 17 | Only BTS categories actually referenced by products (plus ancestors) are created | Products reference 1,834 of 4,103 nodes; the rest would be permanently empty terms |
| 18 | Real cron inside the sillage-core container, WP-Cron disabled | WP-Cron is traffic-triggered and PHP-timeout-bound |
| 19 | Auto-dispatch of vendor orders defaults **off** | Both APIs place real orders with real money and neither has a sandbox |
| 20 | BTS orders stuck in `submitting` after a crash go to `needs_attention`, never auto-retry | BTS accepts no client-supplied reference and exposes no list-orders endpoint, so a retry cannot be proven safe. BeautyFort is fine — its `yourOrderReference` is a real idempotency key |
| 21 | Dashboard owns all configuration; wp-admin gets a read-only status page | One source of truth, and it keeps the plugin thin |
| 22 | Retail multiplier precedence: per-vendor override > matching `price_tiers` band > global multiplier | Client wants cost bands (e.g. ≤€80 × 1.7, above × 1.5) but also per-vendor exceptions. Tiers are operator-editable JSON in `sil_settings`; seed is `[]` so existing installs do not silently change prices. Cost = `vendorPrice × fxRate`; first tier with `maxCost >= cost` wins (`null` = unbounded, last). |
| 23 | Products with no usable image are hidden when `hide_products_without_image` is on | Client: missing photos must not be visible. Sync fills from overrides then cross-vendor EAN matches first; if the resolved URL is still empty/placeholder/**weak BeautyFort `/pic/` thumb**, the product gets the same `exclude-from-catalog` + `exclude-from-search` terms as the stock-threshold rule (OR’d with that rule). Default on. See also decision 27. |
| 24 | Cart minimums live in the PHP bridge; knobs live in sillage | WooCommerce only applies cart fees / checkout validation inside request-time hooks — Bun cannot do it. Deliberate exception to the closed plugin job list (CONTEXT §5 item 8). **Global** floor (`cart_min_*` in `sil_settings`): Foodpanda-style fee when enabled — never blocks checkout; fail-open if settings are unreadable. **Per-vendor** floor (`sil_vendors.order_config.min_order_value_eur`): hard block at cart/checkout with a storefront-label shortfall notice, independent of the global fee toggle. A shop fee cannot satisfy a wholesaler MOQ (dispatch would still reject). Vendor MOQ fails open only when `sil_vendors` itself cannot be read. |
| 25 | wholesale-perfumes cart mutations run under `GET_LOCK('sillage:wholesale-perfumes-cart')`; dry-run does zero remote I/O | The wholesale-perfumes order API is an account-global mutable cart (`DELETE /cart` → `POST /cart` → `GET /cart` → `POST /cart/submit` with optional `{ note }`). Two concurrent dispatches would merge into one wrong order, so the whole sequence holds a MariaDB advisory lock (same pattern as `runSync`). Dry-run builds and records the payload only — it must not empty or touch the cart. There is no client idempotency key (same as BTS): a crash mid-submit goes to `needs_attention` and must never auto-retry. Cart line `code` is the catalog product `id` (vendor B2B API doc; see `docs/vendors/wholesale-perfumes-api.md`). Application `error != 0` on HTTP 200 is a clear reject; HTTP/network failures after mutation stay ambiguous. |
| 26 | Per-vendor configuration lives on the vendor row, not in vendor-named setting keys | Global knobs stay in `sil_settings` and the Settings page. Anything that differs per supplier (multiplier, stock floor, FX, VAT, storefront label, MOQ, serviceable countries, active) is edited on the Vendors page and stored on `sil_vendors` — including JSON keys inside `order_config` when that is the natural home. Daily live-download caps are unused (interval only). Legacy `{slug}_live_max_per_day` keys remain in the schema after migration 014 but are not shown in the dashboard. Active flag and serviceable countries require an in-UI confirmation before save because they decide dispatch eligibility. |
| 27 | BeautyFort `/pic/` thumbs are unusable images — replace or hide, never display | Those URLs are tiny CDN thumbs that break product cards. Sync treats them like placeholders: override → cross-vendor EAN fill → else `null` so `hide_products_without_image` excludes the product. Cross-vendor fill must never index `/pic/` URLs as donors. |
| 28 | Vendor lanes are NOT `product_cat`; B2B is a separate site | Marketplace connectors treat `product_cat` as browse taxonomy — LPS01/LPS02/LPS03 must not live there. Vendor identity is `_sillage_vendor` postmeta only (storefront_label stays in `sil_vendors` for MOQ/cart copy). Do **not** assign visible `pa_vendor` — it leaked LPS labels into WooCommerce Additional information. This shop sells BF/BTS only; wholesale-perfumes is parked (`active=0`, excluded from `--vendor=all`, exclude-from-catalog) for a future B2B site under `b2b-wholesale/`. No `/b2b-wholesale/` page on the retail WordPress. Differentiator for retail vendors remains per-vendor MOQ (decision 24). WPF `product_cat` = feed **type** only when that site exists; brands stay on `product_brand`. Sync purges LPS* product_cat lanes, leftover `pa_vendor` assignments, and WPF `brand:*` product_cat maps. |
| 29 | rewrite-only syncs reload taxonomy maps from the DB | A full rewrite with empty `categoryMaps` deletes every `product_cat` and brand relationship. Settings-driven rewrite-only must call `loadCategoryMapsFromDb` + flat-term loaders, `purgeVendorProductCatLanes`, and `parkWholesalePerfumesFromMainStorefront` before writing. |
